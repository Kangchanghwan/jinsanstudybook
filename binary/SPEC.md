# 이진수 챌린지 구현 명세 (v1)

## 확정 사항
- 디자인: B안 "밝은 보드게임" (`_mockup_B.html`의 비주얼 언어를 그대로 계승: 크림 점무늬 배경, 굵은 검정 외곽선, 원색 카드, 눌리는 그림자 버튼, Black Han Sans + Jua). 단, 전구 ON 상태는 노랑 발광(glow) 효과를 추가해 켜짐이 확실히 보이게.
- 대상: 2학년 고정 (학년 선택 UI 없음, 화면에는 "2학년" 표시만). 반은 1~8 (config.js의 `CLASS_COUNT`로 조절).
- 교과서 쪽수 표기는 전부 제외.
- 범위 4비트(0~15), 자릿값 8·4·2·1. PC(1920x1080 기준, 마우스), 크롬. 1920x1080 고정 무대를 창 크기에 맞춰 scale.
- 플레이 시간 합계 10~20분.
- 최종 배포 경로: `https://진산중학교.kr/binary/` (GitHub Pages 하위 폴더). 모든 경로는 상대경로.

## 파일 구성 (binary/ 폴더)
- `index.html`, `style.css`, `game.js`, `config.js` (빌드 도구 없음, vanilla JS)
- `config.js`: `window.GAME_CONFIG = { API_URL: '', CLASS_COUNT: 8, GRADE: 2 }`. API_URL이 빈 문자열이면 오프라인 모드(기록 전송 생략, 랭킹은 "기록 서버 미연결" 안내 + 로컬 기록만 표시)로 동작해야 함.
- `../apps-script/Code.gs`: Google Apps Script 서버 코드 (아래 API 명세)
- 시안 파일 `_mockup_B.html`은 구현 완료 후 삭제.

## 화면 흐름
1. **입장**: 2학년 표시, 반(1~8 큰 버튼), 번호(1~40 숫자 입력), 이름(필수, 2~10자). 입력값은 localStorage에 저장되어 재방문 시 "이어하기 / 다른 사람으로 시작" 선택. 시작하면 스테이지 맵.
2. **스테이지 맵**: 상단 정보 바(2학년 N반 N번 이름 / 총점 / 별 수). 4개 스테이지 카드(아이콘: 전구·카드·사다리·시계). 순서대로 잠금 해제(이전 스테이지 클리어 시). 클리어한 스테이지는 다시 플레이 가능(최고 점수 갱신). 하단에 "반 랭킹 보기" 버튼.
3. 각 스테이지 시작 전 **방법 안내 카드**(그림+한 줄 설명, "시작!" 버튼). 안내는 짧고 큰 글씨로.
4. **Stage 1 전구 켜기** (8문제): 목표 십진수(1~15, 중복 없이 랜덤) → 전구 4개 클릭으로 ON/OFF. 자릿값 8·4·2·1, 비트 0/1, 수식 "8 + 4 + 0 + 1 = 13" 실시간. 합계 == 목표가 되면 자동 정답 처리(정답 연출 후 다음 문제). 목표 초과 시 "너무 커요" 힌트, 클릭 수가 최적 대비 많으면 감점 요소로 기록.
5. **Stage 2 카드 뒤집기** (8문제, 두 유형 섞기):
   - 유형 A: 목표 십진수 → 점 카드 4장(8·4·2·1개의 점이 그려진 카드)을 클릭해 앞/뒤 뒤집기 → "확인" 버튼. 뒷면 = 0, 앞면 = 1.
   - 유형 B: 카드 4장 상태가 주어짐(이진수) → 십진수를 4지선다 큰 버튼에서 고르기.
   - 오답 시 흔들림 + 풀이 "8 + 0 + 2 + 1 = 11" 표시 후 같은 문제 재도전.
6. **Stage 3 나눗셈 사다리** (5문제, 숫자 5~15): 교과서식 "2로 나누기" 세로 사다리를 단계별로 진행. 각 단계에서 몫(숫자 패드 0~9 큰 버튼)과 나머지(0/1 큰 버튼) 입력. 몫이 0이 되면 마지막에 "나머지를 아래에서 위로 읽기" 단계: 나머지들이 화살표 애니메이션으로 위로 올라가며 결과 이진수 칸에 순서대로 들어감(학생이 나머지를 아래→위 순서로 클릭해서 채우게). 4자리로 맞출 때 앞 0 채우기 설명 표시. 오답 시 해당 칸 흔들림 + 힌트.
7. **Stage 4 타임어택** (60초): 이진수→십진수(0~15 4x4 숫자 버튼) / 십진수→이진수(4비트 토글 + 확인) 랜덤 혼합. 정답 +100 x 콤보배수(1→1, 3연속 x2, 6연속 x3, 최대 x3), 오답 콤보 초기화 + 풀이 0.8초 표시. 10초 이하 붉은 경고. 시작 전 3-2-1 카운트다운. 키보드 숫자 입력도 지원하면 좋음(선택).
8. **스테이지 결과**: 점수(카운트업 애니메이션), 별 1~3개 연출, 정답수/오답수/시간/최고콤보, 기록 전송 상태("기록 저장 중..." → "저장 완료" / "저장 실패, 다시 시도" 버튼). 버튼: 다시 하기 / 스테이지 맵 / (Stage 4 이후) 반 랭킹.
9. **반 랭킹**: 탭 2개. "우리 반 TOP 10"(학생별 총점 = 스테이지별 최고점 합, 1~3위 메달, 내 이름 하이라이트, 내 순위가 10위 밖이면 하단에 별도 표시) / "반 대항전"(반별 평균 총점 막대그래프, 참여 인원 표시, 내 반 강조). 30초마다 자동 새로고침 + 수동 새로고침 버튼.

## 점수·별 규칙
- Stage 1~3: 문제당 첫 시도 정답 100점, 재시도 정답 50점. 클리어 시간 보너스: 기준시간(S1 60초, S2 80초, S3 150초) 이내면 (기준-소요)초 x 2점. 별: 오답 0 = 3개, 1~2 = 2개, 그 외 1개. (Stage 1은 "오답" 대신 목표 초과 횟수를 오답으로 셈)
- Stage 4: 별 기준 점수 1500 이상 3개, 800 이상 2개, 그 외 1개. Stage 4는 플레이만 하면 클리어.
- 로컬에는 스테이지별 최고점/별을 저장. 총점 = 스테이지별 최고점 합.

## 기록 API (Apps Script Web App)
- 시트 탭 `records` 헤더: `시각 | 학년 | 반 | 번호 | 이름 | 스테이지 | 점수 | 정답수 | 오답수 | 소요시간(초) | 최고콤보 | 별 | 기기ID`
- POST: `fetch(API_URL, {method:'POST', mode:'no-cors', headers:{'Content-Type':'text/plain;charset=utf-8'}, body: JSON.stringify({action:'record', ...})})`. no-cors라 응답을 못 읽으므로, 전송 성공(네트워크 에러 없음)이면 "저장 완료"로 처리. 실패 시 localStorage 큐에 쌓고 다음 전송 때 재시도.
- GET: `API_URL?action=ranking&grade=2&cls=3` → `{ok:true, top:[{rank,num,name,total,stars}], me:null, classes:[{cls, avg, count}], updated}`. 서버에서 (학년,반,번호,이름) 단위로 스테이지별 최고점을 구해 합산. 반 대항전 avg는 반별 학생 총점 평균(참여 학생 기준).
- Code.gs: `doPost(e)`는 JSON 파싱 → 입력값 검증(반 1~8, 번호 1~40, 이름 1~10자, 스테이지 1~4, 점수 0~10000) → `LockService`로 append. `doGet(e)`는 랭킹 JSON 반환(`ContentService.createTextOutput(JSON.stringify(...)).setMimeType(ContentService.MimeType.JSON)`). 시트가 없으면 헤더와 함께 생성하는 `setup()` 함수 포함. 성능을 위해 랭킹 결과를 `CacheService`에 20초 캐시.
- 이름은 화면 표시 시 반드시 textContent로 넣을 것(XSS 방지).

## 기타
- 사운드: Web Audio API로 짧은 효과음(클릭, 정답, 오답, 콤보, 카운트다운). 우상단 음소거 토글(기본 켜짐, localStorage 저장). 외부 음원 파일 없음.
- 우상단에 "처음으로"(허브 `../` 링크)와 음소거 버튼. 시안의 P1~P5 개발용 네비는 제거.
- 이모지 사용 금지, 외부 이미지 금지(SVG/CSS로).
- 접근성: 버튼은 button 요소, 주요 텍스트 대비 충분히.
- 개발 편의: URL에 `?debug=1`이면 모든 스테이지 잠금 해제.
