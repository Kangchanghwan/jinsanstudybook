# 이진수 챌린지 v3 변경 명세

## 1. 제곱수(지수) 표기 — 수학적 이해
- 자릿값이 보이는 모든 곳(Stage1 전구, Stage2 카드, Stage3 결과 칸, Stage4 비트 토글, 안내 카드)에서 자릿값 숫자 바로 아래(또는 옆)에 `2³` 형태의 지수 표기를 함께 표시. 예: `8` 아래 `2³`, `1` 아래 `2⁰`.
  - 위첨자는 HTML `<sup>`(또는 유니코드 ⁰¹²³⁴⁵⁶⁷) 사용. 크기는 자릿값보다 작지만 뒷자리에서 읽히도록 최소 30px.
- Stage1·Stage2의 실시간 수식/정답 풀이에 두 번째 줄 추가: `1×2³ + 1×2² + 0×2¹ + 1×2⁰ = 13` (첫 줄 `8 + 4 + 0 + 1 = 13`은 유지). 비트 수가 많아 길어지면 글자 크기 자동 축소(한 줄 유지).
- Stage3 정답 배너 아래에도 같은 지수식 표시.
- Stage4 오답 풀이에도 지수식 표시(짧게).
- 안내 카드 문구에 "자릿값은 2를 거듭제곱한 수예요: 2⁰=1, 2¹=2, 2²=4, 2³=8 ..." 한 줄 추가.

## 3. 비트 수에 따른 게임 변화 (N = 해당 스테이지 bits)
- 자릿값 = 2^(N-1) … 2^0. 최대값 = 2^N - 1.
- **Stage1**: 전구 N개. 목표 = 1..2^N-1 중 서로 다른 수 무작위 (count가 개수 초과면 클램프). 전구 크기/간격은 N에 맞춰 자동 축소(1920 무대 안, 8개도 여유 있게).
- **Stage2**: 카드 N장. 점 카드는 값만큼 점을 격자로(128점까지) — 카드 크기 축소 시에도 점이 뭉개지지 않게 격자 열 수 자동 조정. 유형 B(카드 보고 고르기)의 4지선다 오답 보기는 정답과 1비트 차이 나는 수 위주로.
- **Stage3**: 문제 수 범위 = [max(5, 2^(N-1)) … 2^N-1] (N자리 이진수가 되는 수 위주, 서로 다르게). 사다리는 최대 N단계 — 8단계도 1080 높이 안에 들어가게 행 높이 자동 조정. 결과 칸 N개, 모자라면 앞에 0 채우기.
- **Stage4**:
  - 이진수→십진수: N ≤ 4이면 기존 0~15 4x4 버튼. N ≥ 5이면 큰 숫자 키패드(0~9, 지우기, 확인) + 입력창, 키보드 입력도 지원.
  - 십진수→이진수: 비트 토글 N개 + 확인.
  - 문제 값 범위 0..2^N-1 (0은 너무 쉬우니 1 이상 권장).
- 스테이지 카드와 안내 카드에 "N비트" 배지 표시.
- 점수 공식: 기존 유지하되 Stage1~3 문제당 기본점수는 100 + (N-4)*25 (N<4면 감소), 시간 기준도 N에 비례해 늘림(BASE_PER_Q x N/4). Stage4 별 기준 = 기존 x (sec/60) x (N/4).

## 4. 스테이지 활성/비활성
- 비활성 스테이지는 스테이지 맵에서 **숨김**(카드가 남은 개수에 맞춰 가운데 정렬). 번호는 원래 STAGE 번호 유지.
- 별 총계 분모 = 활성 스테이지 수 x 3.
- 학생이 비활성 스테이지 플레이 중에 설정이 바뀌어도 진행 중인 판은 끝까지.
- 랭킹 총점은 서버 기준 그대로(스테이지별 최고점 합).

## 5. 선생님 설정 페이지 (숨김)
- 파일: `binary/admin.html` + `binary/admin.js` (style.css 재사용 가능, 별도 admin 전용 스타일은 admin.html 안 <style> 또는 style.css 하단).
- **어디에도 링크 금지**(게임, 허브, 보드, 랭킹 화면 모두). `<meta name="robots" content="noindex,nofollow">`.
- 접근 키: URL 해시 `#k=<키>`로 전달. 페이지 로드 시 해시에서 읽어 sessionStorage에 보관하고 `history.replaceState`로 주소창에서 해시 제거(어깨너머 노출 방지). 키가 없으면 "접근 키를 입력하세요" 입력창.
- 로드 시 서버 `POST {action:'adminCheck', key}` → ok면 현재 설정 표시, 아니면 "키가 올바르지 않습니다".
- UI (B안 스타일, 큼직하게, 1920 무대 scale 또는 반응형 — 선생님 PC/노트북용):
  - 스테이지 4행 카드: [켜기/끄기 토글] [스테이지 이름] [비트 수 3~8 칩 버튼] [문제 수 −/+ 스테퍼 (Stage4는 제한시간 초, 10초 단위)] + 현재 비트에서 가능한 숫자 범위 안내 "0 ~ 15".
  - 문제 수 최대값은 비트 수에 따라 동적으로 제한.
  - [저장] 버튼 → `POST {action:'saveSettings', key, settings:{...12개}}` → 성공 시 "저장 완료! 학생이 다음에 시작하는 스테이지부터 적용돼요". [기본값으로] 버튼(확인 후 기본값 채움, 저장은 별도).
  - 활성 스테이지 0개면 저장 막고 안내.
  - 하단에 작은 글씨: "변경 내용은 약 10초 안에 반영됩니다".
- 응답 읽기: `fetch(API_URL,{method:'POST', body:JSON.stringify(...)})`(Content-Type 생략 → text/plain 단순 요청, CORS 모드)로 JSON 응답 읽기. 실패(CORS 등) 시 `mode:'no-cors'`로 보내고 1.5초 후 `GET action=config`로 값이 반영됐는지 확인하는 폴백.

## 6. 서버 (Code.gs)
- `ADMIN_KEY`는 `PropertiesService.getScriptProperties().getProperty('ADMIN_KEY')`에서 읽음. **코드/저장소에 키를 하드코딩하지 말 것.** 키 미설정이면 admin 기능 전부 거부.
- `doPost`의 action 분기: `record`(기존), `adminCheck`, `saveSettings`.
  - adminCheck: 키 일치 시 `{ok:true, config}`.
  - saveSettings: 키 일치 확인 → 각 값 검증·클램프 → settings 탭에 upsert(A열 키 기준 B열 값 갱신, 없으면 행 추가, C열 설명 유지) → config 캐시 삭제 → `{ok:true, config}`.
  - 키 비교는 길이 동일 상수시간 비교 정도로 충분. 실패 시 `Utilities.sleep(500)`로 무차별 대입 둔화.
- 기존 doGet(config/ranking) 응답의 config에 12개 키 포함.
